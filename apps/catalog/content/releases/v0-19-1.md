This patch fixes `BottomNav` indicators that rendered square on Android. It also ships v0.19.0, which extends four web components for large data: `TreeView` loads children on open, `Gallery` selects in batches and loads more, `MessageComposer` attaches, replies and edits, and `MessageList` handles long conversations without jumping. No dependency was added.

## Fixed

- **Android: the selected [`BottomNav`](./bottomnav.html) indicator rendered square** with `capsule` and `circle-bold`. The box that gets painted only had a border radius, so it was flattened into its parent, and when it was created later on selection the radius did not reach Android.
- **The fix**: the icon frame and the `circle-bold` disc now use `collapsable={false}` and exist from mount. This covers the five indicators that paint that box: `capsule`, `circle-bold`, `circle`, `circle-raised` and `circle-outline`. The web never had the bug.

## Includes v0.19.0

### New

- **[`TreeView`](./treeview.html) lazy loading**: `hasChildren` on a node lets it open before it has children. `onExpand(node)` is called on each open; if it returns a promise and the node has no children yet, the node is `aria-busy` with a spinner in place of the arrow until it settles. Children arrive through `items`. A rejected promise closes the node, and opening again retries.
- **`TreeView` controlled selection**: `selectedId` (`string | null`), as in `DependencyGraph`.
- **[`Gallery`](./gallery.html) batch selection**: `selectionMode="multiple"` with `selectedIds` and `onSelectionChange`. Each tile becomes a toggle button (`aria-pressed`) with the usual selected mark; while selecting, a click marks and does not enlarge.
- **`Gallery` videos**: `kind: "video"` and `duration` (seconds) on an item show a `Badge` in the corner with the time as `m:ss`, and "Video" for screen readers.
- **`Gallery` loading more**: `hasMore`, `onReachEnd` and `loading`. A row after the grid notifies when it enters the screen; while loading it shows a spinner and does not notify again; if the new batch does not fill the screen, it notifies again.
- **[`MessageComposer`](./messagecomposer.html) attachments**: `attach` (`true` or `{accept, maxSize, multiple}`) adds a paperclip inside the field. Files sit in a strip above the field, using the `FileInput` row (name, size, image thumbnail, remove). With an attachment, empty text can be sent.
- **`MessageComposer` reply and edit**: `replyTo` with `onCancelReply` shows a quote with a close button; `editing` with `onCancelEdit` puts the old text in the field and turns send into save. Escape cancels both.
- **`onSend` second argument**: `{files, replyToId, editingId}`, only when one of the new props is in use. Code expecting `onSend("text")` still receives exactly that.
- **[`MessageList`](./messagelist.html) message props**: `direction` (`incoming` / `outgoing`; outgoing sits at the end of the row, with no avatar, tinted with the brand), `forwardedFrom`, `replyTo`, `attachments` (photos and videos become a `Gallery` album; files become a `FileInput` row with a download link), `edited` ("edited" next to the time) and `day` (a separator when the day changes).
- **`onOpenAttachment`**: the app opens a photo or video from the album instead of the built-in enlarge.
- **`data-message-id` on every message**, with or without the new props. The list uses it to keep its place, and apps can use it to jump to a message.
- **Sliding window for long conversations**: `hasMoreBefore`, `onReachStart` and `loadingBefore` at the top; `hasMoreAfter`, `onReachEnd` and `loadingAfter` at the bottom. The app keeps a window of messages and swaps at the edges; the list does not jump (the message at the top stays in place, even when a photo grows later), opens at the end and follows new messages when the reader is at the end.
- **Announcements with the window**: the list is no longer a live region; an announcer reads only messages arriving at the end, so older messages loaded at the top are not read aloud.

### Changed

- **`TreeView` items are capsules.** The selected and hover highlights use `--radius-control` instead of `--radius-sm`, like fields, tabs and text buttons.

### Fixed

- **The `TreeView` arrow in right-to-left writing** relied on `:dir(rtl)`, which app bundlers can rewrite. It now flips by the provider's direction (`.tree-twist-rtl`) and turns with the `rotate` property.

### Breaking changes

- **`AureaStrings` (web) has ten new keys**: `chatAttach`, `chatAttachments`, `chatEditCancel`, `chatEdited`, `chatEditing`, `chatForwardedFrom`, `chatReplyCancel`, `chatReplyTo`, `chatSave` and `galleryVideo`. If you build a complete object of this type, add them. Passing a partial object to `AureaProvider` needs no change.
