title: v0.39.0
description: A new typeface on the web — Inter for text, Sora for titles and IBM Plex Mono for code.
date: 2026-10-22
---

Aurea changes its typeface on the web. Text now uses **Inter**, titles use **Sora**, and code uses **IBM Plex Mono**. React Native keeps the previous typeface until the next release.

## ⚠ May break

- **The web no longer loads Atkinson Hyperlegible.** `@aurea-uds/fonts/css` now declares `Inter`, `Sora` and `IBM Plex Mono`. If your own CSS names `"Atkinson Hyperlegible Next"` or `"Atkinson Hyperlegible Mono"`, it falls back to the system font: use the tokens instead (`var(--font-ui)`, `var(--font-heading)`, `var(--font-code)`).
- **Every heading from `h1` to `h6` now uses Sora**, both Aurea's and your app's, through a zero-specificity rule (`:where(h1,h2,h3,h4,h5,h6)`). A font set on the heading itself (a class, an `h1` rule) wins over it. A font the heading only inherits, such as one set on `body`, does not: to keep your font in headings, set it on them.
- **`numeric` and the figure of a `KPI` now use IBM Plex Mono**, with digits of the same width: on `Text`, `Heading`, `Paragraph` and `Code`, it is meant for values and identifiers. Other numbers (tables, counters, pagination, calendars) stay in Inter, also with digits of the same width. In a table, give `numeric` to the value cells that should use IBM Plex Mono (`<Text numeric>`). IBM Plex Mono ships in weights 400, 500 and 600; bold uses 600.
- **React Native tokens already name the new fonts** (`fontUi` Inter, `fontHeading` Sora, `fontCode` IBM Plex Mono), but the font files do not change until v0.39.1. If your app passes `fontFamilies` to `AureaProvider` (the package's `FONT_FAMILIES`, as the example does), nothing changes: headings use the text map too. If it does not, the device is asked for families it does not have yet, and falls back to the system font until v0.39.1.
- **Text measures change slightly.** At text size Inter is wider than Atkinson Hyperlegible: about 7 to 9% for a sentence at 14px in the regular weight, 4 to 5% in semibold. Labels, tabs and table cells take a little more room. From 30px up Inter is narrower. The figure of a `KPI` is now IBM Plex Mono (above), so this does not apply to it.
- **In `DependencyGraph`, a node's type line (the uppercase one, such as "ACCESS SWITCH") may wrap to two lines** where it used to fit in one: Inter's capitals are wider. The node grows taller and the map a little larger. Nothing of the text is cut. Font sizes and line heights do not change.

## Changed

- **`--font-ui` is Inter**, the variable font with optical sizes from 14 to 32. **`--font-heading` is Sora**, variable from 100 to 800. **`--font-code` is IBM Plex Mono**, in weights 400, 500 and 600. `--font-editorial` remains an alias of the text font until 1.0.
- **`@aurea-uds/fonts`** ships six new web files. Inter and Sora are variable fonts, so one file covers every weight, including the 800 of `--weight-extrabold`. They are cut to the Latin set the web served before, 218 characters, and keep every design feature, such as tabular figures. Inter has 217 of them (the original has no division slash) and Sora 217 (no thin space, which falls back to Inter). The IBM Plex Mono files are IBM's own Latin-1 files, unchanged, and cover 214 of the 218. All three are under the SIL Open Font License 1.1, and the package `LICENSE` carries each copyright.
- **The contract** (`aurea.contract.json`) names the new fonts and adds the `heading` role.

## Not changed

- **React Native font files stay Atkinson Hyperlegible until v0.39.1.** `@aurea-uds/fonts/native` and its `.ttf` files are the same as before; only the token names changed (above).
